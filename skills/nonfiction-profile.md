# Nonfiction Project Profile

Load this reference only when `<project-root>/.book-writer/project.json` has `"profile": "nonfiction"`. The `fly-night-fishing` preset uses the physical `world/` folder as a **Knowledge Base**.

## Global rules

1. Read the project configuration and relevant Knowledge Base files before acting.
2. Preserve the author's lived voice and practical vocabulary. Do not turn field experience into generic authority-sounding prose.
3. Never invent a catch, trip, location, quotation, observation, credential, or lesson. Mark missing details as an open question.
4. Treat the author's firsthand account as a valid attributed source. Label it as observation or recollection rather than silently converting it into a universal claim.
5. Require jurisdiction, checked date, source, and verification status for safety, access, legal, and fishing-regulation claims. Flag stale or missing verification; do not guess current rules.
6. Distinguish personal technique preferences from generally applicable advice. Preserve disagreements and regional variation.
7. Keep stable nonfiction IDs: `TOP` topic, `TEC` technique, `EQU` equipment, `SPEC` species, `COND` condition, `PLC` place, `PER` person, `ANE` anecdote, `CLM` claim, and `SRC` source. Never casually renumber them.
8. Treat `world/continuity/decision-ledger.md` as binding project memory. Surface contradictions instead of overwriting them.

## Workflow translation

- **Intake:** classify notes, interviews, photographs, and transcripts into the configured buckets. Retain source wording and provenance.
- **Outline enhancement:** develop reader promise, topic progression, instructional prerequisites, demonstrations, and story placement. Do not manufacture narrative drama.
- **Human gate:** ask the author to confirm audience, scope, organization, omissions, anecdote use, and unresolved factual boundaries.
- **Planning:** give each chapter learning goals, prerequisite topics, practical demonstrations, stories, terminology, safety callouts, claims needing verification, and voice anchors.
- **Writing:** clearly signal experience versus general instruction. Use unresolved markers rather than plausible inventions.
- **Review:** assess practical usefulness, progression, redundancy, safety, provenance, internal consistency, and voice. Do not critique the absence of a fictional character arc.
- **Editing:** keep correctness/verification work separate from optional style advice, and preserve approved experiential language.
- **Formatting/output:** support parts, chapters, procedures, lists, cautions, sidebars, and narrative passages without imposing novel-only conventions.

Use the existing workflow's stable review and edit IDs (`RV`, `EP`, and related event IDs) for traceability.
